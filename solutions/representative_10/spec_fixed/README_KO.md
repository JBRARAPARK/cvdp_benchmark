# 자판기 사양 기준 수정본

이 폴더는 이전 `first/` 및 공식 테스트 호환 `revised/`와 구별되는 수정본입니다. 기존 공식 문제·테스트는 변경하지 않습니다.

## 명시한 인터페이스 해석

- 모든 입력은 상승 에지에 샘플링하며, 출력은 그 에지의 레지스터 갱신 후 관측합니다.
- `item_button` 상승을 샘플링한 다음 클록에 상품 ID를 샘플링합니다. 별도 selection_valid가 없으므로 이 시점의 0, 5, 6, 7은 모두 유효하지 않은 선택입니다. 무기한 선택 대기와 0의 즉시 오류를 동시에 구분할 수 없는 원문 인터페이스의 모호함에 대한 명시적 해석입니다.
- `coin_input=0`은 동전 없음입니다. 1/2/5/10은 한 클록에 한 번 수락합니다. 0을 오류로 취급하면 유휴 상태를 표현할 수 없어 이렇게 정의합니다.
- 상품 가격은 이전과 같이 5/10/15/20입니다. 원문에는 가격표가 없고 공식 테스트에만 있습니다.
- 결제금액 충족 다음 에지에 상품을 배출하며, 거스름돈은 배출 바로 다음 에지에 반환합니다.
- 상품 ID는 리셋, 다음 거래 시작, 오류/취소 환불 완료 전까지 유지합니다. 정상 거래의 ID 출력 유효 기간은 원문에 명시되지 않았으므로 읽기 가능성을 위해 이 규칙을 사용합니다.
- 배출 신호가 아직 발생하지 않았다면 취소가 우선합니다. 취소와 동전이 같은 에지에 들어오면 해당 동전은 수락하지 않고 기존 잔액을 반환합니다.
- 결제 중 잘못된 액면의 동전은 오류와 반환 신호를 같은 클록에 출력합니다. 환불액은 이미 수락한 잔액이며 잘못된 액면값은 잔액에 더하지 않습니다.
- 선택 전 동전은 오류 후 다음 클록에 반환합니다. 선택 버튼과 동전의 동시 입력도 선택 전 투입으로 처리합니다.

## 변경

1. CHANGE_WAIT 제거: 거스름돈을 배출 바로 다음 클록에 반환.
2. 잘못된 ID를 동전 없이도 선택 샘플링 시점에 거절.
3. DISPENSING_ITEM 대기 상태에서도 취소 수락: 실제 배출 전 취소 가능.
4. 상품 ID 유지 및 새 거래 시작 때 초기화 규칙 명시.
5. 오류, 배출, 반환 출력은 기본값으로 매 클록 해제하여 한 클록 펄스 보장.
6. 정상 반환 및 취소/오류 반환 후 잔액 정리, 비동기 리셋 처리.

## 테스트 방식

`tb_vending_machine.sv`는 입력을 하강 에지에 설정하고 상승 에지 후 1ns에 출력값을 검사합니다. 공식 Cocotb 테스트처럼 상승 에지 직후 값을 읽거나 동시에 입력을 바꾸는 스케줄링 모호함을 피합니다.

검증 범위: 4상품의 정액/초과 결제, 연속 거래, 모든 잘못된 ID, 모든 잘못된 비영(非零) 동전값, 선택/결제/배출 직전 취소, 버튼 및 취소 신호 유지, 선택 전 동전, 선택 버튼과 동전 동시 입력, 거래 도중 비동기 리셋.

## 검증 결과

- 수정본 독립 테스트: **32 시나리오, 156 assertion 통과**.
- 같은 테스트에 기존 revised 답안을 넣으면 `change exactly one cycle after dispense`에서 실패: 기존 문제를 검출하는 회귀 테스트임을 확인.
- 원본 공식 테스트: **실패**. 내부 pytest 10회 중 6회는 거스름돈 시점, 4회는 잘못된 상품 선택 오류 시점 검사에서 중단.
- 이는 두 검증 기준의 차이를 보여줍니다. 공식 테스트는 추가 대기 후 반환과 늦은 오류 관측을 요구하고, 이 수정본은 명시한 사양 해석대로 바로 다음 클록 반환 및 선택 샘플링 시점 오류를 구현합니다.
- 공식 테스트와 문제 원문은 수정하지 않았습니다. 독립 테스트는 원문과 위에서 명시한 가정의 검증이며, 공식 점수를 대체하지 않습니다.
